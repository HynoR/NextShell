# NextShell 2 界面设计

更新:2026-11-12。**取代此前的 Termius 式设计(主机侧栏 + 右侧面板 + 状态栏)**,那一版留在 git 历史里。

## 定调

产品负责人试用 2.0.0-rc1 后的结论:「这个 2.0 只是个用 mygo 写的 shell,而不是 mygo 重构的 nextshell」。

**2.0 的布局参照 1.x:1.x 用户在 2.0 里,该有的功能还在原来的位置。**

- 「抛弃 v1 包袱」指技术包袱(IPC、Electron 绕路、旧数据层、v1 数据迁移),不是产品设计。
- 只有两种情况可以不照搬,每条都单列在「例外」里,由产品负责人批准:
  - mygo 难以实现;
  - v1 原设计本身有问题。
- 引擎沿用 2.x,不回退,放进 v1 的位置:冲突安全保存、⌘K 命令面板、Agent 策略、导入导出、互操作修复。

审计依据:用 v1 自身的渲染器(1440×900 暗色)离屏截图,与 v2 `TestScreenshots` 对照。v1 参照图为 `20-workspace-connected.png`。

## 连接管理器窗口(「服务器」/ ⌘O)

```
┌ 连接管理器 ───────────────────────────────────────────────────────────────────────────┐
│ [作用域: 本地 ▾](仅开启云同步时)   [ 连接 | 密钥 | 代理 ]                              │
├──────────────┬─────────────────────────────────────────────────┬───────────────────────┤
│ 目录       ⊕ │ [+ 新建连接] [>_本地终端] [⌕ 名称/地址/用户/标签…] [导入▾][导出▾] │ 详情 / 编辑            │
│ ◷ 最近连接    │ ┌ 已选 2 · [绑定认证] [导出] [删除] ┐(选中 ≥2 时出现)         │ 名称 主机 端口 用户    │
│ ▾ 本地    6  │  🖥★prod-web-01  🖥 prod-web-02  🖥 db-master             │ 认证 [私钥▾]           │
│   ▸ 生产  3  │  🖥! legacy-box(私钥认证但没有可用密钥)                 │ 密钥 [▾] +新建/生成     │
│   ▸ 测试  1  │                                                          │ ▸ 安全 ▸ 网络(代理 +新建)│
│              │                                                          │ ▸ 终端(编码/BS/Del/监控)│
│              │                                                          │ ▸ 标签 收藏 备注        │
│              │                                                          │[保存并连接][保存][取消] │
└──────────────┴─────────────────────────────────────────────────┴───────────────────────┘
```

- **密钥页:**
  - 表格:名称 / 类型 / 指纹 / 被引用。
  - 详情:被引用列表、公钥;操作:复制公钥、重命名、替换私钥、删除。
- **代理页:**表格 + 编辑表单;被引用的代理不能删除。
- **认证分离:**数据模型已经是 `KeyID` / `ProxyID` 引用,只需改界面和导入路径。
  - 编辑表单第一屏就能选密钥,旁边「新建 / 生成…」,创建后直接选中;代理旁边「新建代理…」。
  - 新主机默认沿用上次的认证方式和密钥。
  - 密钥按指纹去重,重复导入时提示「已存在,已选用」。
  - 导入的私钥主机找不到密钥时,仍保持私钥认证并标红;之后导入密钥时,按指纹或名称自动绑定。
  - 批量绑定认证可以从多选或目录发起,先预览目标主机;代理默认「保持不变」。
- 设置里的「密钥」「代理」「导入导出」移到这里,设置里只留跳转链接。

## 其它窗口与工具

| 功能 | 位置 |
|---|---|

## 视觉

- 指标颜色沿用 v1:CPU 蓝、内存绿、交换靛、磁盘青;超过 70% 变琥珀,超过 90% 变红。
- 网络:↑ 橙,↓ 绿。
- 地址和数值用等宽字体;分区标题用小号大写(「系统监控」「PING 延迟」)。
- 标签和磁贴上显示每台主机的颜色点。
- 强调色:设置里可选几种预设主色,默认 v1 蓝 `#4d9fff`(已定问题 1)。
- 明、暗两套主题都要截图验收。

## 例外(已批准 2026-11-12)

1. **连接管理器做成独立窗口,不用 v1 的大模态框。**mygo 的 `Dialog` 不适合大尺寸、可缩放的模态;入口不变。
2. **设置保持独立窗口。**原因同上。
3. **监控探针拆成轻、重两种。**v1 每 2 秒常驻跑全量探针,太重。改为轻探针常驻;重探针(`ps` / `ss`)只在进程或网络管理器打开时跑。
4. **批量绑定认证增加代理字段,默认「保持不变」。**v1 没有这个字段,属于改进。
5. **监控网格(多会话只读预览)延后。**取决于 mygo 终端能否提供第二个只读视图。
6. **窄窗口下底部工作区不做自适应**,太矮时靠拖动。
7. **左右栏折叠后留 40px 窄条**,左右一致。
8. **主机颜色标记用竖条**,不用圆点,避免与状态点混淆。
9. **管理器窗口先带简易详情面板**,P1 扩展。

## 已定问题(2026-11-12)

1. **强调色:**内置几种主色供用户在设置里选,默认 v1 蓝 `#4d9fff`;rc1 青色作为其中一个选项。明暗两套都要成立。
2. **连接管理器:**独立窗口。
3. **内置编辑器:**默认做主窗口标签,可弹出到新窗口。
4. **可复用的「用户名 + 密码」凭据:**延后,先靠密钥、代理和批量绑定解决复用。
5. **进程 / 网络管理器:**做成会话标签,同 v1。

## 文案

写给用户看,不出现实现术语(v1、OSC、keepalive 三态、AAD)。常驻位置只放状态、不放警告;自动批准徽标是例外,开启期间必须常驻。
