# NextShell 2 产品路线(MVP → 成品)

更新:2026-11-12。本文件取代 `docs/v2/` 下各阶段报告(PHASE*/V1-*/GUI-*/UI-*),那些报告保留在 git 历史中。

## 定位

NextShell 2 是**全新产品**,不是 1.x 的升级版。

- 不读取、不迁移 1.x 数据库、设备密钥、钥匙串。
- 与 1.x 的桥只有两座:① 1.x 导出连接文件 → 2 导入(已完成);② 可选:从云端一次性拉取部分数据(连接、命令片段)。
- 1.x 的**布局和产品设计照搬**(见 `DESIGN.md`),技术实现和数据模型不照搬。UI 文案里不出现 "v1"、"OSC"、"keepalive 三态" 这类实现术语。

## 2.0.0 阶段计划(2026-11-12)

**rc1 的问题:**布局和产品设计偏成了 Termius 式,丢了 1.x 的精髓:

- 认证分离;
- 常驻的服务器实时状态;
- 醒目的会话状态;
- 实时编辑列表;
- 终端下方的文件区。

**决定:**2.0 布局参照 1.x(见 `DESIGN.md`)。每个阶段结束时应用都完整可用,可以单独发 rc。

每个阶段的格式:目标 → 范围 → 验收(用户可见)→ 依赖 / 规模。编号 B / I / N 对应 `DESIGN.md` 的审计条目:B 为阻塞发布,I 为重要,N 为加分项。

### P1 连接管理器与认证分离 ✅ 2026-11-12(e721b80…772e87c)

**目标:**解决「每加一台服务器都要重复添加密钥 / 代理」。

**范围:**

- **B4:**管理器窗口做成 v1 结构:
  - 目录树(最近连接、计数、右键批量绑定);
  - 主机磁贴网格,支持多选和批量操作条,私钥认证但没有密钥的磁贴显示红标;
  - 详情卡;
  - 编辑表单,字段顺序同 v1,监控开关、Backspace / Delete 模式;
  - 密钥页和代理页从设置搬来,包括「被引用列表」和「替换私钥」;
  - 导入导出,支持拖入 .json;
  - 从多选或目录发起的批量绑定,先预览再应用。
- **B5:**
  - 内联「新建 / 生成密钥」「新建代理」,创建后直接选中;
  - 新主机默认用上次的认证方式和密钥。
- **B6:**
  - 密钥按指纹去重;
  - 导入的私钥主机保持私钥认证并标红;
  - 导入密钥后按指纹或名称自动重新绑定;
  - 支持「为 N 个主机选择密钥」。
- **I4:**认证失败后可以换用户、认证方式或已有密钥,并写回主机。
- **B10 可复用凭据:**
  - 新实体「凭据」:名称、用户名、认证方式(密码 / 密钥 / agent / 键盘交互)、密码(存钥匙串 / 加密存储,同主机密码)或密钥引用;
  - 主机可选「使用凭据」,选中后用户名和认证取自凭据,表单里只读显示;不选则保持主机自带认证;
  - 管理器加「凭据」页(与密钥、代理并列),显示被引用列表;删除被引用的凭据需确认并把主机退回自带认证;
  - 批量绑定可选凭据(默认「保持不变」);新建主机可内联新建凭据;
  - 云同步、导入导出、⌘K、MCP 连接都按解析后的凭据连接;导出不含明文密码。

**验收:**

- 用同一把密钥加 10 台主机:不进设置,也不重复导入。
- 同一私钥导入两次,提示「已存在」。
- 建一个「用户名 + 密码」凭据,批量绑定到 50 台主机;改一次密码,50 台都用新密码连接。
- 导入 1.x 连接,再导入密钥,这些主机无需逐台编辑即可连接。
- 设置里不再有密钥、代理、导入导出页(只留链接)。

**依赖 / 规模:**依赖 P0;L。

**P1 结果:**

- 管理器窗口分「连接 / 密钥 / 代理 / 凭据」四页;连接页为目录树 + 主机磁贴 + 右侧详情卡 / 编辑表单。截图:`16-manager*`、`08/09/10-host-editor*`、`18-manager-keys`、`19-manager-credentials*`、`13c-auth-retry`。
- 凭据在每条连接路径(界面、⌘K、MCP、重连、复制会话)都在平台层解析;云同步加密携带;导出把凭据随主机带上,密码只在加密导出里。
- 主机表单的「监控服务器状态」开关已写入 `Connection.Monitor`,新主机默认开启;是否采样由 P2 决定。
- 未做:管理器顶部的「作用域」选择(只在开发版云同步下出现,随云同步排期);磁贴的主机颜色竖条(模型里还没有主机颜色,随 P4 I6)。

**P1 例外**(2026-11-12 定案:1、2、4、5 批准,3 驳回):

1. **磁贴只能从图标拖到目录。**mygo 的网格单元格整体可拖时会吞掉单击选择,所以拖动手柄放在磁贴左侧的服务器图标上;也可右键「移动到」。
2. **删除凭据时,没有自带用户名的主机拿到凭据的一份拷贝**(用户名、认证、密码 / 密钥),其余主机退回自带认证。否则这些主机删除后无法连接。
3. **导出时主机自身的用户名 / 认证 / 密码也写成凭据的值**,以便 1.x 能导入;2.0 导入时按名称复用或新建凭据并绑定,主机自带一份同样的认证作为后备。
4. **认证失败的重试对话框只对用户发起的连接弹出;**Agent(MCP)发起的连接把错误交回 Agent,不打扰用户。
5. **FinalShell 导入的私钥主机也保持私钥认证并标红**(此前改为键盘交互)。

### P2 服务器实时状态 ✅ 2026-11-12(cd8c3fb…04b5b65)

**目标:**左栏就是 1.x 的系统监控,其余工具回到原位。

**范围:**

- **B3 后半:**
  - `Connection.Monitor` 开关生效,默认开启,编辑表单里有开关;
  - 按主机保存历史,切回某主机时立刻显示上次数据,并标「缓存数据」;
  - 网卡选择;
  - `Meter` 条使用 v1 指标配色;
  - 网络图。
- **I1:**PING 卡,点击打开路由追踪抽屉。设置里只保留 nexttrace 路径。
- **I2:**进程管理器、网络管理器做成每台主机一个标签,从监控按钮打开,关闭标签即停止重探针。
- 「系统信息」标签:静态信息加历史曲线。

**验收:**

- 连上 Linux 主机后,不用打开任何东西就能看到每 2 秒刷新的状态。
- 关掉某台主机的监控开关后,不再采样。
- 能在左栏看到 ping 延迟,点击后对这台主机做路由追踪。

**依赖 / 规模:**依赖 P0;M。可与 P1 并行。

**P2 实现说明:**

- `Connection.Monitor` 仍是 `monitorSession`,含义是「开启」。读取时缺字段按开启处理(`Connection.UnmarshalJSON`),写入时总是写出,所以显式关闭不会丢。新建主机、快连、没有该字段的导入都默认开启。P1 的编辑表单要绑定 `Monitor`,新建主机的初值要带 `Monitor: true`(`hosts.go` 新建处已改一个字)。
- 缓存数据按主机保存在内存里(重连、切换标签、关闭标签后仍在),重启应用后不保留。
- PING 卡的延迟是 SSH keepalive 往返时间,随每次采样测一次,所以监控关闭时显示「—」。

**P2 例外**(2026-11-12 全部批准):

1. **延迟不用 ICMP。**用 SSH keepalive 往返:走真实路径(含代理),不需要系统放行 ICMP,Windows 也不需要提权。代价:监控开关关闭时没有延迟;值包含服务器处理 keepalive 的时间。
2. **工具标签放在会话标签之后,且跟随主机。**进程 / 网络标签打开时,左栏切到该主机,会话重连后标签保留,主机最后一个会话关闭时标签一并关闭;⌘W 关闭当前显示的工具标签,不关会话。
3. **重探针按「标签是否存在」运行**(不是「标签是否可见」):标签在后台时仍每 2 秒采一次完整样本,关闭标签才停止。
4. **「连接中」标签只是状态指示**,不可点击、不可取消(平台层目前没有取消连接的接口)。首次连接且没有任何会话时,中间区域显示「正在连接…」。
5. **路由追踪抽屉盖在左栏右侧**,不是左栏内部展开;Esc 或关闭按钮关闭,关闭时中止追踪。找不到 nexttrace 时提示去「设置 → 网络工具」。设置页「网络诊断」改名「网络工具」,只保留 nexttrace 路径(原来的 Ping / 路由追踪输入框删除)。

### P3 工作区工具 ✅ 2026-11-12(P3a 6fb8f03…33f3983,P3b f84fcc6…5063335)

**目标:**补齐终端下方和右栏的 1.x 工具。

**范围:**

- **B7:**SFTP 增加目录树。
- **I3:**命令输入栏:历史持久保存,支持 ↑/↓;⌘⇧F 查找终端回滚。
- **B8:**右栏 Agent 活动:调用流水、批准 / 拒绝、紧急停止;收起时显示计数徽标。
- **B9:**实时编辑登记表和列表:
  - 监听不依赖编辑器进程是否在运行;
  - 状态:监听中 / 同步中 / 已同步 / 冲突 / 出错;
  - 冲突时可选覆盖远端、重新载入、另存本地;
  - 支持停止单个和全部断开;
  - 默认用系统文本编辑器,无需先配置。

**验收:**

- 右键 → 远程编辑,无需配置就能打开。
- 每次保存后,列表显示「同步中」再变为「已同步」。
- 关闭编辑器 App 不会悄悄停止同步。
- 输入栏的历史重启后仍在。

**依赖 / 规模:**依赖 P0;M–L。

**P3a 结果**(B7、I3、取消连接;6fb8f03…33f3983):

- 终端下方命令输入栏:回车发送到当前会话,历史与「发送命令」共用并持久保存(全局,最多 100 条,重复命令移到最新),↑/↓ 浏览,重启后仍在。截图 `25-command-bar-history`。
- ⌘⇧F 或输入栏的查找按钮打开查找栏:搜索屏幕与回滚,显示「第 N / 共 M」,上一个 / 下一个,回车 / ⇧回车,Esc 关闭。用的是 mygo 终端自带的搜索,无需改上游。截图 `26-find-bar`。

**P3a 例外**(2026-11-12 全部批准):

1. **⌘⇧F 改为查找终端内容**,不再切到底部 SFTP 标签(P0 的映射)。SFTP 标签没有单独的快捷键,⌘J 打开工作区后点选;⌘⇧M / ⌘⇧S 不变。
2. **命令历史全局共用,不分主机**,与「发送命令」对话框是同一份。
3. **目录树只显示真实文件夹,不显示指向文件夹的链接**(链接可能指向任意位置,解析后路径会与树对不上)。
4. **快速连接(未保存的主机)没有「连接中」标签,因此不能取消**;取消只针对已保存主机。

**P3b 结果**(B8、B9;f84fcc6…5063335,分支 `v2-p3b`):

- **B8:**右栏「Agent 活动」直接读网关自己的记录(记录里加了目标名和命令摘要),不另建数据:待批准卡片可就地批准 / 拒绝;最近 10 条调用(时间、主机、命令或动作、结果);「紧急停止」拒绝待批准、关闭自动批准并中止正在运行的命令,停止后可「恢复 Agent」。收起时 Agent 图标显示待批准数。截图 `24a/24b-*`。

**P3b 例外**(2026-11-12 批准;1 已在合并时改为「远程编辑」):

1. **右键菜单项仍叫「用外部编辑器打开」**,没有改成「远程编辑」:`panel_files.go` 归 P3a,合并时改一个词即可。
2. **右栏只显示最近 10 条调用**,完整历史仍在「设置 → Agent」。
3. **紧急停止不二次确认**,停止后右栏直接给「恢复 Agent」。

6. **「重新载入」直接改写本地副本**,编辑器是否自动刷新取决于编辑器本身。
7. **连接断开期间保存显示「出错」**,不排队重试;下次保存或重连后再保存即可。

### P4 打磨与 2.0.0 发布

**N1 结果**(2026-11-12,分支 `v2-n1`):

- **做法:**用 mygo 终端插件的 `Mirror`。每个会话一个「画面」终端,由该会话终端的 `Mirror` 帧逐格喂养(只读:连接丢弃一切输入和应答),再用变换整屏等比缩小进磁贴。没有退回到文本快照。
- **`Mirror` 的约束与对策:**
  - `Mirror` 的帧会取走终端「哪些行变了」的记录,会话自己的视图也读这份记录,所以网格盖住标签栏以下的整个区域(终端和底部工作区),显示期间没有任何会话的视图在画。
  - 退出网格时先关闭全部镜像和画面终端,再给每个会话终端换一份内容相同的新主题:视图见到没应用过的主题就整屏重画。实测不这样做,退出后视图会保留进入网格前的行(与从没开过网格的应用相比有上千个像素不同);换主题不会改变程序用 OSC 设置的颜色(已验证)。`TestGridLeavesTheSessionViewIntact` 逐像素对照。
- **入口与退出:**标签栏最右的「监视网格」按钮(网格显示时高亮)、命令面板「显示 / 隐藏监视网格」。Esc、点磁贴(含画面)、点标签栏任一标签都会退出;点磁贴 / 标签进入对应会话。
- **磁贴:**标题(`tabTitle`)、主机颜色竖条、状态点;当前会话有主色边框并带键盘焦点(Tab / Shift+Tab 在磁贴间移动,回车进入);已断开或已退出的会话显示最后一屏,变暗并标「已断开」(「已退出」「连接中」同理)。
- **尺寸:**按每个会话的实际终端大小算缩放比例,选使平均缩放最大的列数(1 个会话:整个区域;4 个:2×2;9 个:3×3;12 个:4×3);磁贴最小 200×120,超过后网格上下滚动。
- **频率与开销:**每个会话每 250 ms 取一帧(终端没变化时一帧约 0.1 ms);首次出图要读完会话的整个滚动缓冲(默认 10 MiB 约 20 ms,256 MiB 约 0.5 s),所以每个界面帧最多花 24 ms,其余磁贴顺延到下一帧。画面终端不留滚动缓冲、不写系统剪贴板。
- **清理:**退出时 `Mirror.Close`、画面终端 `Close`;测试逐轮检查四种退出方式后镜像不再出帧、画面终端已结束、goroutine 数回到进入前。
- **测试**(`grid_test.go`、`shots_n1_test.go`):开关(按钮和命令面板)、点击激活(标题 / 画面文字 / 空白处)、Esc(含命令面板、对话框在上时只关它们)、网格期间没有任何输入到达任何会话(键盘、⌘L、⌘⇧F、Tab,退出后输入仍正常)、镜像和 goroutine 清理、画面与会话屏幕一致(含大量滚动输出)、频率、已断开显示、退出后视图逐像素无差别、尺寸规划 1–30 个会话、标签随会话增减。
- **与 N2 背景图:**画面终端和其余终端一样是 `Transparent`,磁贴底色用 `terminalGround`、标题条用 `pane`、网格底用 `page`:没有背景图时与原来逐像素相同,有背景图时磁贴随滑块半透明(`TestGridTilesPaintTheTerminalGround` 在明 / 暗下核对磁贴底色就是终端配色的背景)。
- 截图 `n1-1-grid-4`(4 个会话,其中 1 个已断开)、`n1-2-grid-9`、`n1-3-grid-14`、`n1-4-grid-4-picture`(背景图上的 4 个会话)(明 / 暗)。
- **限制:**
  - 磁贴是整屏缩略图,典型 100×30 的终端在 2×2 时约缩小到 0.6,3×3 时约 0.4,字很小,看细节要点开。
  - 进入网格会让每个会话回到底部(`Mirror` 取帧时把视口滚到底);之前向上翻看滚动缓冲的位置不保留。

## 决策记录(2026-11-12)

## 分工

按改动规模选子 agent(产品负责人偏好,2026-11-12):
